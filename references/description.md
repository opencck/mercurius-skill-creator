# Описание скилла

Описание — одна строка до 120 символов в каталоге каждой беседы. По нему ты решаешь, открывать ли скилл. Слабое
описание — скилл не срабатывает; размытое — срабатывает не там и тратит токены.

## Как писать

- Что делает **и когда** звать: «Выкладка сервисов на сервер: git pull, сборка, миграции, проверка — при просьбе
  выложить или обновить сервис».
- Слова, которыми владелец просит такую работу, а не внутренние названия.
- Чуть настойчивее, чем кажется нужным: модели чаще недо-, чем переоткрывают скиллы.
- Без «этот скилл …», без перечисления всего, что внутри.

## Проверка срабатывания

Составь короткий список запросов (8–12):

- **должен сработать** — разные формулировки той же просьбы, включая косвенные;
- **не должен** — близкие, но другие задачи (самые полезные: соседние темы, где легко ошибиться).

Для каждого реши по одному описанию, открыл бы ты скилл. Где ошибся — уточни описание: добавь слово-признак или
границу («не для …»). Покажи владельцу спорные случаи, если не уверен, где граница.
